1. 这次要完成什么

这一套流程是改良德尔菲，同时用 RAND/UCLA 适宜性方法（RAM）的核心规则判断一致和分歧。它要和另外两条已经存在的流程分开：

  • 普通 Delphi 用高区比例、中位数和四分位距。入口是 run_delphi()。
  • 经典 RAM 专家组通常是两轮，第 2 轮在面对面会议之后复评。入口是 run_rand()，场景是 rand_ucla。
  • 本教程的入口是 delphi_ram_protocol("table4") 和 run_delphi_ram()。是否走这条路，由你在第 1 轮前选定。选定之后不能再交回 run_delphi() 或 run_rand()。

表 4 来自 Fitch 等（2001）。它按这一条的实际应答人数查两个数：包含中位数的 3 分区间以外最多允许多少人，才叫一致；1–3 分和 7–9 分两端至少各有多少人，才叫分歧。9 人属于 8–10 人档：区外不超过 2 人为一致，两端各至少 3 人为分歧。

适宜性仍是：中位数 7–9 且无分歧为适宜；1–3 且无分歧为不适宜；中位数 4–6，或任何分歧，为不确定。正向共识、负向共识、未达成共识只是这些结果的报告名称。无分歧不等于一致。 适宜不要求先达到那个更严格的“一致”。

样本是 simulate_delphi_ram("table4")。安装后同一份数据也可以 data(delphi_ram_table4_demo)。9 名专家、6 条陈述、三轮匿名函询。它不是真实指南。

library(delphir)
ram <- simulate_delphi_ram("table4")
ram

解读： 场景是 delphi_ram。目的写的是用表 4 判断适宜性，流程是三轮函询，不是把专家关在一间会议室里开两轮。

2. 先锁定方案，再发问卷

p <- ram$protocol
p

#>   结合 RAM: 是；规则: table4；函询: mail；最多 3 轮
#>   临床 high_pct 不参与本场景分类。
#>   锁定: 是
p$combine_ram
#> [1] TRUE
p$rand$rule
#> [1] "table4"
p$rand$round2_mode
#> [1] "mail"
p$stability$max_rounds
#> [1] 3
p$rules$high_pct
#> [1] NA

解读：

  • combine_ram = TRUE 表示这是独立的改良德尔菲结合 RAM，不是在普通共识阈值上临时加一个开关。
  • 规则是 table4。函询形式是 mail：再次寄送问卷，没有面对面会议。这是对经典 RAM 的流程偏离，报告里会写明。
  • 最多 3 轮。第 3 轮可以存在，但不是用来把分歧投票掉。
  • high_pct 是 NA。临床共识的 80% 高区比例写在对象里只是为了对照，不参与分类。看见结果接近某条线，再把阈值改掉，是不允许的。

若有人把这种研究交给普通入口，软件会停下来：

tryCatch(run_delphi(ram), error = function(e) conditionMessage(e))
#> [1] "这是改良德尔菲结合 RAM。请使用 run_delphi_ram()，不要使用 run_delphi()。"
tryCatch(run_rand(ram), error = function(e) conditionMessage(e))
#> [1] "这是改良德尔菲结合 RAM。请使用 run_delphi_ram()，不要使用 run_rand()。"

解读： 两条错误信息都指向 run_delphi_ram()。这样不会把表 4 的分歧悄悄换成高区比例，也不会把三轮函询当成经典两轮专家组。

3. 第 1 轮问卷

第 1 轮不展示别人的分数。问卷说明里已经写上锁定规则。docx 用来发放，xlsx 用来回收。

#> [2] "C:\\Users\\Lenovo\\AppData\\Local\\Temp\\RtmpGKKk7n\\ram-table4-bca8571a14af/round1.xlsx"

解读： 两个文件都在。评分维度是「适宜性」：1 表示预期危害远大于获益，9 表示预期获益远大于危害。无法判断要单独勾选，不能填 5 分充数，也不进入中位数和分歧的分母。

4. 把第 2 轮问卷读回来

真实项目里，专家在 xlsx 里填写后再用 read_survey_xlsx() 读入。这里用已经生成的第 2 轮分数做预填，演示读回后能接上第 1 轮，而不是覆盖第 1 轮。

base <- ram
base$ratings <- base$ratings[base$ratings$round == 1, ]
q2 <- delphi_ram_questionnaire(ram, round = 2, format = "xlsx",
                               file = file.path(qdir, "round2.xlsx"), prefill = TRUE)
back <- read_survey_xlsx(q2, study = base)
sort(unique(back$ratings$round))
#> [1] 1 2
nrow(back$ratings)
#> [1] 108

解读： 读回后同时有第 1 轮和第 2 轮。第 1 轮没有被盖掉。空白的新一轮如果和已有轮次重复，软件会拒绝覆盖。第 2 轮问卷仍然包含全部 6 条，不会因为某条在第 1 轮已经适宜就把它拿掉。这是 RAM 的做法，和普通 Delphi 只重评「未决议」条目不同。

5. 第 1 轮每一条是什么意思

r1 <- classify_delphi_ram(ram, round = 1)
r1[, c("item_id", "median", "n_low", "n_high", "n_out", "agreement_max",
       "disagreement", "agreement_status", "class_zh", "consensus_zh")]
#>   item_id median n_low n_high n_out agreement_max disagreement agreement_status
#> 1    ST01      8     0      9     0             2        FALSE        agreement
#> 2    ST02      2     9      0     0             2        FALSE        agreement
#> 3    ST03      5     0      0     0             2        FALSE        agreement
#> 4    ST04      5     4      4     8             2         TRUE     disagreement
#> 5    ST05      8     3      6     3             2         TRUE     disagreement
#> 6    ST06      7     0      6     3             2        FALSE    indeterminate
#>                       class_zh             consensus_zh
#> 1                         适宜                 正向共识
#> 2                       不适宜                 负向共识
#> 3 不确定（中位数 4–6，无分歧） 未达成共识（中位数居中）
#> 4           不确定（存在分歧）   未达成共识（存在分歧）
#> 5           不确定（存在分歧）   未达成共识（存在分歧）
#> 6                         适宜                 正向共识

解读： 9 人，agreement_max 是 2，disagreement 用的是两端各至少 3 人。

  • ST01：中位数 8，低区 0 人，高区 9 人。无分歧，而且区外人数没有超过 2。适宜，一致，报告用语是正向共识。
  • ST02：中位数 2，9 人都在低区。无分歧。不适宜，报告用语是负向共识。负向共识是明确的反对，不是「没填完」。
  • ST03：中位数 5，两端都是 0。分数集中在 4–6，所以 agreement_status 可以是 agreement，但适宜性仍是不确定（中位数居中）。共识用语是未达成共识。大家意见接近「不好说」，不是达成了正向共识。
  • ST04：中位数 5，是因为 1–3 与 7–9 各有 4 人。这是分歧，不是「中等意见」。未达成共识（存在分歧）。
  • ST05：中位数 8，但低区有 3 人。表 4 判分歧。中位数再高，只要存在分歧，分类就是不确定，不能写成适宜。
  • ST06：中位数 7，低区 0 人，所以无分歧，适宜性是适宜，共识用语是正向共识。但有 3 个 6 分落在 7–9 以外，超过了「区外不超过 2 人」，因此 agreement_status 是 indeterminate，不是 agreement。这就是「无分歧不等于一致」。本方案没有把一致写成适宜的必要条件。

sens <- res$sensitivity

#>   item_id  class_table4   class_ipras class_percent matches_locked
#> 1    ST01   appropriate   appropriate   appropriate           TRUE
#> 2    ST02 inappropriate inappropriate inappropriate           TRUE
#> 3    ST03     uncertain     uncertain     uncertain           TRUE
#> 4    ST04     uncertain     uncertain     uncertain           TRUE
#> 5    ST05     uncertain   appropriate     uncertain          FALSE
#> 6    ST06   appropriate   appropriate   appropriate           TRUE
sens$note
#> [1] "敏感性分析不替换已锁定规则。若两套规则结论不同，正式结果仍按第 1 轮前写入方案的那一种。"

解读：

  • 锁定规则是 table4。κ 比较的是适宜 / 不确定 / 不适宜是否相同，不是比较中文句子。
  • ST05 在表 4 下是不确定，在 IPRAS 下是适宜。这不是计算错误。分布整体偏高时，IPRAS 会放宽分歧阈值。既然方案写的是表 4，正式结论保持不确定。
  • ST06 在表 4 下是适宜，在百分比规则下是不确定：6/9 约 67% 落在 7–9，没有达到 70%。百分比是另一套修改版规则，这里只作敏感性，不改已经锁定的表 4。
  • matches_locked = FALSE 的条目，就是「换规则会变」的条目。看到这个结果之后再去改规则，是事后选择。

10. 和真实项目的差别

这份样本没有人中途退出，也没有「无法判断」。真实数据里，某条只有 6 个人作答时，软件会警告人数不足 7，分类只供描述。7 人沿用 8–10 人的阈值，报告里要写明。超过 16 人的阈值是外推，手册没有正式列出那一档。

若第 2 轮实际开了会，把 round_mode 写成 in_person 或 online，不要把开过的会写成函询，也不要把函询写成开过会。
