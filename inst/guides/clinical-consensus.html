教学文档 1：医学专家共识 Modified Delphi 全流程

Ming Yang

2026-11-27

1. 这份文档解决什么问题

本教程从零演示如何用 delphir 完成一项医学专家共识（Modified Delphi）：

  1. 先写清问题、使用者和地理范围；
  2. 在看数据之前锁定共识阈值；
  3. 读入（或模拟）专家、条目、评分和意见；
  4. 计算参与度、Median / IQR / 赞同率；
  5. 按复合标准判定高度共识、基本共识、临界、排除、两极分化；
  6. 看稳定性、分层和脱落偏倚；
  7. 制作下一轮受控反馈；
  8. 输出符合 ACCORD 结构的报告，并解读每一张表。

使用的样本是包内数据集 consensus_demo：40 名专家、20 条临床试验质量条目、两轮 9 分 Likert。数据故意不完美，含脱落、无法判断、临界条目和两极分化。

2. 方法学边界：Delphi 不是证据评价

Delphi 适合回答的是：

在证据不足、不一致，或即使有证据仍需做价值判断时，如何系统整合多位专家的判断。

它不适合代替系统评价或 GRADE。比较稳妥的框架是：

证据检索与评价 → 形成候选条目 → Delphi → 共识会议 → 定稿

本示例的 meta$evidence_note 记录了条目来自法规与方法学综述后的初始条目池，对应 Modified Delphi（第一轮即评分），而不是经典 Delphi 的开放式第一轮。

3. 第一步：预先锁定方案（不可事后改阈值）

Diamond 等的系统评价表明，文献里的共识定义差异很大，最常见阈值中位数约为 75%。正确原则不是“必须 ≥70%”，而是第一轮前写明阈值及其理由。

医学专家共识推荐复合标准，而不是只看一个百分比：

  • 高度共识：P(7–9) ≥ 80%，且 Median ≥ 7，且 IQR ≤ 2
  • 基本共识：75% ≤ P(7–9) < 80%，且 Median ≥ 7
  • 倾向排除：P(1–3) ≥ 75%
  • 两极分化：两端同时达到 25%
protocol <- preset_protocol("clinical_consensus")
protocol
#> Delphi 分析方案
#>   场景: clinical_consensus (医学专家共识（Modified Delphi）)
#>   量表: 1–9  (低 1–3 / 中 4–6 / 高 7–9)
#>   新增条目: 允许；≥2 人独立提出，或 1 人且有外部证据；至少两轮评分后才能最终纳入
#>   锁定: 是

如果发卷前就把 80% 写成 85%，那是本研究的初次锁定，不必写 rationale。锁定之后再改，才用 revise_protocol()，报告会打印“方案偏离初次锁定”。

initial <- preset_protocol("clinical_consensus", high_pct = 0.85)
initial$modified_from_preset
#> [1] FALSE

stricter <- revise_protocol(
  initial,
  high_pct = 0.90,
  rationale = "方案锁定后、看见评分前，将高度共识从 85% 提高到 90%。"
)
stricter$modified_from_preset
#> [1] TRUE

常见错误： 看到结果后把阈值改成“刚好能过”的 75%。这在方法学上不成立。classify_consensus() 也没有阈值参数，防止分析阶段静默改规则。

5. 参与度：积极系数与更重要的脱落

part <- response_summary(consensus_demo)

#> 1     1        40          40         100.0                100.0            70

part$retention
#>   from_round to_round n_previous n_retained n_lost n_new retention_rate
#> 1          1        2         40         37      3     0           92.5

解读：

  • 第 1 轮 40/40 = 100%，第 2 轮 37/40 = 92.5%。国内常称“专家积极系数”，本质就是回收率，值得报告。
  • 对 Delphi 更关键的是 retention：37/40 = 92.5%。若脱落集中在某一利益相关者组，最终共识可能被扭曲。
  • DCAT 把专家保留作为附加质量项。
plot_attrition(consensus_demo)

authority_scales()$ca
#>           source        key large medium small
#> 1       实践经验   practice   0.5    0.4   0.3
#> 2       理论分析     theory   0.3    0.2   0.1
#> 3 参考国内外文献 literature   0.1    0.1   0.1
#> 4       直观感觉  intuition   0.1    0.1   0.1

解读：

  • \(Cr=(Ca+Cs)/2\)。Ca 来自判断依据（实践/理论/文献/直觉），Cs 来自熟悉程度。默认赋分见表；必须在第 1 轮前锁定。
  • 按专家评一次，不要对每个条目再填一套。条目不熟请勾选「无法判断」（unable），不要再算条目级 Cr。
  • 国内常以组均数 0.70 为参考。DCAT 的四个核心特征是匿名、迭代、受控反馈、统计汇总，不包括 Cr。
  • Cr = 0.90 不能证明专家选择科学；构成偏差（例如全是同一专科）才是更大问题。不要用 Cr 加权 1–9 分，第 2 轮也不必重评权威系数。
  • 若问卷里是「较熟悉 / 大 / 中 / 小」勾选而不是现成小数，用 score_authority() 赋分。从空白问卷到第 2 轮反馈单的完整流程见 vignette("questionnaire-workflow", package = "delphir")。

解读每一列：

  • n_valid：真正进入 1–9 的人数；n_unable 单独报告。
  • median_iqr：如 8 (7–9) 表示中位数 8、四分位距从 7 到 9。Likert 是有序数据，Median 通常优于 Mean。
  • p_high / p_low：7–9 与 1–3 的百分比。分布比“平均分 8.1”信息量大得多。
  • cv：SD/Mean，国内常用补充指标。有序数据上 Median+IQR 更稳健。
  • polarized：两端同时 ≥25%。均数接近 5 往往不是“大家觉得一般”，而是严重分裂。

解读分类，而不是只看“过没过”：

  • 高度共识 / keep： 原则上下一轮可不再重评，或仅确认；共识会议不应轻易推翻。
  • 基本共识 / keep： 过了 75% 但未达 80% 或 IQR 偏大，写入共识时语气宜保留弹性。
  • 临界 / discuss： 70%–75% 一带，机械删除最危险。应先读自由意见、改表述，再进入下一轮。
  • 两极分化 / discuss： 说明存在稳定的价值冲突，正确结论可能就是“未形成共识”。
  • 倾向排除 / drop： 低区达 75%，倾向删除，仍应记录反对理由。

9. 为什么不能只看平均分或 Kendall W

构造一个教学对照（不是本数据集）：

detect_polarization(p_high = c(0, 50), p_low = c(0, 50))
#> [1] FALSE  TRUE
coefficient_variation(c(8, 8, 8, 8))
#> [1] 0
coefficient_variation(c(1, 1, 1, 9, 9, 9))
#> [1] 0.8763561

Kendall W 评价的是一组项目的相对排序是否协调，适合优先级排序。本例问题是“每条是否重要”，W 只能当补充。

解读： “我赞成本条，但仅适用于高风险干预性研究”不是反对，而是条件性支持。ACCORD 要求说明自由文本如何做内容/主题分析。delphir 只汇总你已经编码的 theme，不会用黑盒模型替你定性。

方法学组据此修改条目后，必须把修改理由反馈给专家，这才是受控反馈的一部分。

  • Median 从 7 到 8、IQR 从 3 到 1、高区从 68% 到 83%，说明共识在增强。

plot_round_shift(res, metric = "p_high")

18. 本场景对应的常见错误

  1. 第一轮前没有预设阈值；
  2. 根据结果回改 75%；
  3. 只报 Mean±SD；
  4. 把 Kendall W 的 P 值当成共识；
  5. 把 Cr 当成科学性主证据；
  6. 专家全来自同一专业；
  7. 反复投票直到全部“达成共识”；
  8. 第二轮没有反馈第一轮结果；
  9. 面对面会议推翻 Delphi；
  10. 不报告脱落。
